# LoadingState

La espera de un bloque **cuya forma no se conoce**: una página, una vista, el
cuerpo de un diálogo, una hoja o un popover cuyo contenido aún no ha llegado.
Un girador centrado en una caja que reserva alto y, si hace falta, una salida.

<Canvas of={LoadingStateStories.PorDefecto} />

## Esqueleto o girador

Cuando **sí** se conoce la forma de lo que llega (una tabla, una lista, una
ficha), no se usa esto: se reserva su sitio con esqueletos dentro de un
`LoadingRegion`, y la página no salta al llegar el contenido. El girador queda
para lo que no tiene forma conocida y para la espera de una acción, y en ese
caso va **dentro del control** (`Button loading`).

Un `Spinner` nunca se suelta en el flujo: es `inline-flex`, no reserva alto y
queda arriba a la izquierda. `LoadingState` es la caja que lo centra.

## Por defecto, solo se ve el girador

El texto de la espera **no se pinta**: es el nombre accesible de la caja
(`role="status"`, `aria-busy="true"`, `aria-labelledby` apuntando al texto
oculto) y es lo que anuncian los lectores de pantalla. El girador va
decorativo, para no anunciar la espera dos veces.

`label` cambia el texto («Cargando revisión…», con puntos suspensivos: ver
Foundations → Redacción). Sin `label`, sale de `spinner.label` del
`BrandMessagesProvider` — el mismo texto que el `Spinner`. Fuera del proveedor (una
página de error global) conviene pasar `label`; sin él ni catálogo, sale el
castellano de respaldo del paquete («Cargando…») y avisa en desarrollo: nunca
se queda sin nombre.

<Canvas of={LoadingStateStories.ConTexto} />

## Texto visible para esperas largas

`labelVisible` pinta el `label` bajo el girador, centrado, con el texto atenuado
de la descripción de `EmptyState` (sus mismos tokens: `loading-state.label-*`).
Es para una espera **larga y con pasos**, donde el texto informa de por dónde
va: «Procesando el documento: paso 2 de 5…», «Importando el curso: 14 de 38
lecciones…». En una espera corta **no se usa**: un texto que aparece y
desaparece en un segundo es ruido.

- **Es el mismo nodo** que da el nombre accesible: no se anuncia dos veces. La
  caja es `role="status"` con `aria-live="polite"` y `aria-atomic="false"`, así
  que cuando `label` cambia (el paso siguiente) se anuncia solo el texto nuevo,
  con cortesía, sin releer la acción; y si el texto no cambia entre renderizados,
  el DOM no se toca y no se repite.
- **Sin `label` propio no pinta nada.** El texto genérico del catálogo
  («Cargando…») es justo el que se quitó de la vista; con `labelVisible` y sin
  `label`, la espera sigue como siempre (solo girador, texto oculto) y no es un
  error de desarrollo.

<Canvas of={LoadingStateStories.TextoVisible} />
<Canvas of={LoadingStateStories.TextoVisibleConAccion} />

```tsx
<LoadingState
  label={`Procesando el documento: paso ${paso} de ${total}…`}
  labelVisible
  action={{ label: 'Cancelar', onClick: cancelar }}
/>
```

## Tallas

`md` (por defecto) para una página o una zona; `sm` para el cuerpo de un
diálogo, una hoja, un popover o una barra lateral. Cambian el girador, el alto
mínimo que se reserva y el relleno.

## Con acción

Una salida mientras se espera: cancelar un proceso largo. La acción sí se ve,
y es un `Button` `outline` de la talla de la espera. Recibe el mismo
`EmptyStateAction` que `EmptyState`.

## Alto y centrado

El girador sale centrado en los dos ejes. Para que el centrado vertical sea
real, la caja ocupa el alto de la zona que sustituye. Hay tres casos:

**En una zona con alto definido**, la caja la ocupa entera (`block-size: 100%`,
y `flex: 1` si la zona es una columna flex) y centra en ella. Sin prop.

<Canvas of={LoadingStateStories.EnZonaConAlto} />

**En un flujo sin alto**, el porcentaje no resuelve: la caja reserva el mínimo
de su talla (`loading-state.min-height`, `sm-min-block-size`) y centra en
él.

<Canvas of={LoadingStateStories.EnFlujo} />

**A página completa**, `fill`: la caja toma el alto visible bajo la cabecera
del `AppShell` (la ventana menos el cromo del armazón, que el shell publica en
`--app-shell-chrome-block-start`, y menos el relleno de sección del contenido)
y centra en él sin provocar desplazamiento, aunque llegue envuelta en otros
elementos del layout. Es la espera del `loading.tsx` de una ruta cuya forma no
se conoce. Fuera del `AppShell` la variable no existe y vale cero.

<Canvas of={LoadingStateStories.PaginaCompleta} />

```tsx
// app/(app)/editor/[id]/loading.tsx
export default function Loading() {
  return <LoadingState fill />;
}
```
