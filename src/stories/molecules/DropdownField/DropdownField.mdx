# DropdownField

Campo desplegable: una etiqueta y un control **rectangular a la altura del sistema** que abre un `Menu`. Es el hermano del `SelectField` para cuando las opciones no caben en un `<select>` nativo: llevan icono, son enlaces o acciones, o el valor elegido se muestra con algo más que texto. Su cara es la del Select —mismo borde, misma altura, mismo chevron— para que los dos convivan en un formulario sin que se note cuál es cuál.

<Canvas of={DropdownFieldStories.PorDefecto} />

## Etiqueta

Encima por defecto, como el resto de campos. `inline` la pone delante, para barras y paneles donde el campo va solo (es como lo usa `ThemeSwitcher`). `labelHidden` la deja para los lectores de pantalla; y si no hay etiqueta, `aria-label` es obligatorio: el control nunca se queda sin nombre.

<Canvas of={DropdownFieldStories.SinEtiqueta} />

## Tallas

`size` es la talla del sistema: `sm` 32, `md` 40 (por defecto) y `lg` 48, con el cuerpo y el padding del Select. **En las superficies públicas** —la web y el hub sin autenticar— los controles van a `lg`; **dentro de las aplicaciones**, a `md`.

<Canvas of={DropdownFieldStories.Tallas} />

## Contenido del control

`children` es lo que se ve en el control: normalmente el nombre de la opción actual, con su icono si lo tiene. El componente no lo deduce de `items` porque el control puede decir algo distinto de la opción (un resumen, un contador).

<Canvas of={DropdownFieldStories.ConIcono} />

## Opciones

`items` son los del `Menu`: `radio` para elección exclusiva (con `value`/`onValueChange`), `button` para acciones, `link` para navegar. La cara del menú desplegado es la del `Menu`, no la del Select.

<Canvas of={DropdownFieldStories.Deshabilitado} />

## Ayuda y error

Como el resto de campos: `helperText` describe; `errorMessage` avisa (`role="alert"`) y pone el control en error por sí solo —`error` sirve para marcarlo sin mensaje—. Los dos quedan enlazados por `aria-describedby`, y el error también por `aria-invalid`, que es lo que le pinta el borde. En línea, ayuda y error siguen debajo, ocupando la fila entera.

## Con react-hook-form

El control abre un `Menu` de Base UI, así que el contrato **no** es el spread del `field`: es `value` / `onValueChange` + `name` + `ref` al disparador. El `name` monta además el input oculto que se envía con el formulario.

```tsx
<FormField
  control={form.control}
  name="orden"
  render={({ field, fieldState }) => (
    <DropdownField
      ref={field.ref}
      name={field.name}
      value={field.value}
      onValueChange={field.onChange}
      onBlur={field.onBlur}
      disabled={field.disabled}
      label="Ordenar por"
      items={items}
      errorMessage={fieldState.error?.message}
    >
      {etiquetaActual}
    </DropdownField>
  )}
/>
```

## Accesibilidad

- La etiqueta va enlazada por `htmlFor`/`id` al disparador; sin `id`, el campo genera uno con `useId`. Sin etiqueta visible, `aria-label` es obligatorio.
- Los `id` de ayuda y error se derivan del del campo (`<id>-helper`, `<id>-error`) y llegan al control por `aria-describedby`, en ese orden.
- El mensaje de error se anuncia (`role="alert"`) y marca el control con `aria-invalid`.

## Cuándo no

- Si las opciones son texto plano y solo hay que elegir una: `SelectField`, que es un `<select>` de verdad.
- Si el trigger no debe parecer un campo (un avatar, un código de idioma en la barra): `Menu` directo con el trigger que toque.
