# MultiSelectField

El `MultiSelect` como campo de formulario: etiqueta, disparador con las opciones elegidas en píldoras, ayuda y error, con el mismo ritmo que el resto de campos. Es el que se usa en formularios; el átomo suelto, solo fuera de ellos.

Cuando la lista de opciones no cabe en memoria y hay que buscarla en el servidor, el campo es `AsyncMultiSelectField`.

<Canvas of={MultiSelectFieldStories.PorDefecto} />

## Etiqueta

Siempre hay etiqueta (`label`) y **por defecto se ve**. El disparador es un `div` con `role="combobox"` —lleva píldoras dentro, no puede ser un `<button>`—, así que `htmlFor` no bastaría para nombrarlo: el campo lo enlaza además por `aria-labelledby`. Sin `id`, genera uno con `useId`.

<Canvas of={MultiSelectFieldStories.EtiquetaOculta} />

## Ayuda y error

`helperText` describe; `errorMessage` avisa (`role="alert"`) y pone el control en error por sí solo —`error` sirve para marcarlo sin mensaje—. Los dos quedan enlazados por `aria-describedby`, y el error también por `aria-invalid`. El borde en error lo pone el propio control.

## Valor

Sin `value`, el campo se gobierna solo (`defaultValue` fija el arranque). Con `value` + `onValueChange`, manda el consumidor.

## Con react-hook-form

El control es de Base UI, así que el contrato **no** es el spread del `field`: es `value` / `onValueChange` + `name` + `ref` al disparador. El `name` monta además un input oculto por valor elegido, que es lo que se envía con el formulario.

```tsx
<FormField
  control={form.control}
  name="servicios"
  render={({ field, fieldState }) => (
    <MultiSelectField
      ref={field.ref}
      name={field.name}
      value={field.value}
      onValueChange={field.onChange}
      onBlur={field.onBlur}
      disabled={field.disabled}
      label="Servicios"
      options={options}
      errorMessage={fieldState.error?.message}
    />
  )}
/>
```

## Accesibilidad

- La etiqueta nombra el disparador por `aria-labelledby` (y apunta a su `id` por `htmlFor`).
- Los `id` de ayuda y error se derivan del del campo (`<id>-helper`, `<id>-error`) y llegan al control por `aria-describedby`, en ese orden.
- El mensaje de error se anuncia (`role="alert"`) y marca el control con `aria-invalid`.
- El texto del botón que quita una píldora es traducible con `removeLabel`. Ese botón vive **fuera** del elemento con `role="combobox"`: un combobox no admite controles dentro.
- Teclado del patrón combobox: ↓/↑ abren y recorren, Inicio/Fin saltan a los extremos, Intro y Espacio marcan y desmarcan, Escape cierra y escribir una letra salta a la opción que empieza por ella. El foco del DOM no se mueve de la caja — la opción activa se señala con `aria-activedescendant`.
