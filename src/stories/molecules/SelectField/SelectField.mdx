# SelectField

El `Select` como campo de formulario: etiqueta, control, texto de ayuda y mensaje de error, apilados con el mismo ritmo que el resto de campos (`InputField`, `TextareaField`…). Es el que se usa en formularios; el átomo suelto, solo fuera de ellos.

<Canvas of={SelectFieldStories.PorDefecto} />

## Etiqueta

Siempre hay etiqueta (`label`), enlazada por `id`; sin `id`, el campo genera uno con `useId`. `labelHidden` la deja solo para los lectores de pantalla cuando el contexto ya dice qué es el campo.

<Canvas of={SelectFieldStories.EtiquetaOculta} />

## Ayuda y error

`helperText` describe; `errorMessage` avisa (`role="alert"`) y pone el control en error por sí solo —`error` sirve para marcarlo sin mensaje—. Los dos quedan enlazados al control por `aria-describedby`, y el error también por `aria-invalid`. El borde en error lo pone el propio `Select` a partir de ese `aria-invalid`, en el color de texto de error, nunca un fondo.

<Canvas of={SelectFieldStories.ConError} />

## Opciones agrupadas

`options` acepta, además de opciones sueltas (`{ value, label }`), grupos con cabecera (`{ label, options }`), y las dos formas se mezclan en la misma lista. La cabecera es una **etiqueta**, no una opción: no se elige ni la enfoca el teclado, y nombra a su grupo (`role="group"` + `aria-labelledby`).

```tsx
<SelectField
  label="Tipografía"
  options={[
    { label: 'Fuentes del tema', options: [{ value: 'heading', label: 'Titulares' }] },
    { label: 'Fuentes del sistema', options: [{ value: 'sans', label: 'Sans-serif' }] },
  ]}
/>
```

<Canvas of={SelectFieldStories.ConGrupos} />

## Valor vacío

Una opción con `value: ""` sirve de «sin elegir» (el primer ítem de la lista). El campo la traduce internamente para que el `Select` la acepte y devuelve `""` en `onValueChange`.

`size` viaja al `Select`: el control mide 32, 40 o 48, las tallas del sistema.

## Con react-hook-form

El control es de Base UI, así que el contrato **no** es el spread del `field`: es `value` / `onValueChange` + `name` + `ref` al disparador (para que react-hook-form pueda enfocarlo al fallar la validación). El `name` monta además el input oculto que se envía con el formulario.

```tsx
<FormField
  control={form.control}
  name="contrato"
  render={({ field, fieldState }) => (
    <SelectField
      ref={field.ref}
      name={field.name}
      value={field.value}
      onValueChange={field.onChange}
      onBlur={field.onBlur}
      disabled={field.disabled}
      label="Tipo de contrato"
      options={options}
      placeholder="Selecciona un tipo"
      errorMessage={fieldState.error?.message}
    />
  )}
/>
```

## Accesibilidad

- La etiqueta va enlazada por `htmlFor`/`id` al disparador.
- Los `id` de ayuda y error se derivan del del campo (`<id>-helper`, `<id>-error`) y llegan al control por `aria-describedby`, en ese orden.
- El mensaje de error se anuncia (`role="alert"`) y marca el control con `aria-invalid`.
- Las cabeceras de grupo son etiquetas, no opciones: no son parada del teclado y nombran a su grupo por `role="group"` + `aria-labelledby`.

## Tokens

El campo solo aporta el ritmo (`gap`) y los textos de ayuda y error, que referencian los de `form.*`; el control es el `Select`.
