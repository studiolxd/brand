# CheckboxField

El `Checkbox` como campo de formulario: marca, texto de la opción, ayuda y error. El label no lleva mayúsculas ni el tamaño reducido del `Label` de formulario — usa la tipografía de texto por defecto para integrarse en flujos de lectura (términos, privacidad, opciones de contacto).

El disparador de Base UI es un `<button role="checkbox">` de verdad y lleva el `id`, así que la etiqueta lo nombra por `htmlFor`; sin `id`, el campo genera uno con `useId`.

## Ayuda y error

`helperText` describe; `errorMessage` avisa (`role="alert"`) y pone el control en error por sí solo —`error` sirve para marcarlo sin mensaje—. Los dos quedan enlazados por `aria-describedby`, y el error también por `aria-invalid`. El error se marca en el borde de la casilla, en el color de texto de error.

## Con react-hook-form

El control es de Base UI, así que el contrato **no** es el spread del `field`: es `checked` / `onCheckedChange` + `name` + `ref` al disparador (para que react-hook-form pueda enfocarlo al fallar la validación).

```tsx
<FormField
  control={form.control}
  name="terminos"
  render={({ field, fieldState }) => (
    <CheckboxField
      ref={field.ref}
      name={field.name}
      checked={field.value}
      onCheckedChange={field.onChange}
      onBlur={field.onBlur}
      disabled={field.disabled}
      label="Acepto los términos y condiciones"
      errorMessage={fieldState.error?.message}
    />
  )}
/>
```

## Accesibilidad

- El texto está enlazado por `htmlFor`/`id`.
- Los `id` de ayuda y error se derivan del del campo (`<id>-helper`, `<id>-error`) y llegan al control por `aria-describedby`, en ese orden.
- El mensaje de error se anuncia (`role="alert"`) y marca el control con `aria-invalid`.

## Theming oscuro

En modo oscuro, el color del label se reasigna automáticamente vía los tokens `surface-dark-*` bajo `.surface-dark`. No requiere prop adicional — basta con que un ancestro tenga `.surface-dark`.
