# Stepper

El progreso de un flujo por pasos: dónde está el usuario, qué lleva hecho y qué le queda. Es la pieza que acompaña a un alta, a un asistente o a una compra en varias pantallas.

<Canvas of={StepperStories.PorDefecto} />

## No es `Steps`

Son dos piezas distintas y ninguna sustituye a la otra:

| | `Steps` | `Stepper` |
| --- | --- | --- |
| Qué hace | **Documenta** un proceso: los pasos de una metodología, de una matrícula | **Acompaña** a un flujo en marcha |
| Estado | No tiene: ningún paso es «el actual» | Completado / actual / pendiente |
| Contenido | Título, descripción, cuerpo rico | Una etiqueta corta y, si acaso, una línea |
| Dónde vive | Una página de contenido, un MDX | La cabecera de una plantilla de flujo |

## Estados

Los estados no se pasan: se deducen de `current`. Lo anterior está completado, lo posterior pendiente. Cada estado se distingue por **dos** señales, nunca solo por el color: la marca (rellena con un check, rellena con la cifra, hueca con la cifra) y el peso de la **etiqueta**, que es lo que dice dónde está el usuario sin depender del color. La **cifra** de la marca va en peso de cuerpo: dentro de un círculo relleno de otro color el peso no señala nada, y ponerlo en énfasis solo empastaba las cifras del paso actual y de los pendientes.

El carril entre pasos dice lo mismo que las marcas y con su mismo color: el tramo recorrido lleva la marca del sistema —el relleno de un paso hecho—, y el que queda por recorrer, el rol de borde —el filete de una marca pendiente—. No es un fondo: un filete de 1px tiene que contrastar con el lienzo, no armonizar con él, así que no usa la escala de superficies.

## Adaptativo

Por debajo de `md` no caben cuatro etiquetas en fila, así que el progreso degrada a su forma compacta: el contador y la etiqueta del paso actual. Solo una de las dos formas está en el árbol a la vez, así que un lector de pantalla nunca oye el progreso dos veces. El texto del contador es una prop (`compactLabel`), no una cadena fija: recibe el número de paso y el total.

**Con un solo paso no se pinta nada.** Un «paso 1 de 1» es ruido, y una plantilla no debería tener que preguntárselo: monta siempre el hueco del progreso y es el flujo quien decide si hay algo que contar. Es lo que permite que `OnboardingShell` sirva igual para el alta de cuatro pasos y para la sala de espera.

## Qué pasos se pueden alcanzar

Con `onStepSelect` los pasos alcanzables se vuelven botones. Sin el callback, el progreso solo informa.

**Por defecto son alcanzables los completados**: volver a corregir el nombre que se puso dos pantallas atrás siempre se puede.

<Canvas of={StepperStories.VolverAtras} />

Hacia delante ya no es blanco o negro, porque depende del flujo y no del componente: hay altas donde el orden no obliga y otras donde el paso 4 no existe hasta que el 2 ha creado la organización. Eso no lo puede adivinar el `Stepper` —abrirlos todos llevaría al usuario a un paso que no puede completarse—, así que **lo declara cada paso** con `reachable`:

```tsx
<Stepper
  current={paso}
  onStepSelect={(index) => setPaso(index)}
  steps={[
    { id: 'perfil', label: 'Perfil' },
    { id: 'organizacion', label: 'Organización' },
    { id: 'logotipo', label: 'Logotipo', reachable: true },        // se puede rellenar cuando sea
    { id: 'invitaciones', label: 'Invitaciones', reachable: hayOrg }, // no existe sin la organización
  ]}
/>
```

- Sin declararlo, lo de siempre: alcanzables los completados.
- `reachable: true` abre un pendiente; `reachable: false` cierra un completado (un paso hecho que ya no se puede tocar).
- **El paso actual nunca es alcanzable**, se declare lo que se declare: ya se está en él, y un botón que no lleva a ningún sitio solo añade una parada al tabulador.
- Alcanzable no es un estado. Un pendiente abierto sigue pintándose pendiente —marca hueca, etiqueta secundaria—: lo que cambia es que se puede pulsar, no dónde está el usuario.
- Un paso al que aún no se puede llegar es **inerte**, no un botón deshabilitado: un `<span>` sin `role`, sin foco y sin cursor de mano. Un deshabilitado promete algo que no se puede hacer y ensucia el recorrido de teclado; un destino que todavía no existe simplemente no es un destino. Y no lleva señal nueva: el estado del paso ya se ve.

La regla habitual del producto es «hacia delante solo con el paso actual completo»: mientras quede un campo obligatorio por rellenar, los siguientes van con `reachable: false`, y en cuanto el paso valida se abren. Esa decisión es del flujo, que es quien conoce sus campos y sus dependencias; el `Stepper` no valida nada, obedece.

Va en el paso y no en una prop del componente porque es un hecho de ese paso, como su etiqueta: el flujo ya construye la lista con su propio estado, y una función aparte sería una segunda fuente de verdad viviendo lejos de los datos que la deciden.

## Accesibilidad

- Es un `ol` de verdad: el orden y el total los anuncia el navegador, no una cadena escrita a mano.
- El paso actual lleva `aria-current="step"`.
- El estado de cada paso se anuncia con un texto oculto («Completado», «Paso actual», «Pendiente»), traducible por `labels`: sin él, el estado viviría solo en el color y en la forma.
- Un paso alcanzable es un `<button>` nativo, con su anillo de foco. Uno inerte no es un botón ni recibe foco: es un `<span>`, así que el tabulador solo se para en lo que lleva a algún sitio.

## Cómo se usa

```tsx
<Stepper
  steps={[
    { id: 'perfil', label: t('perfil') },
    { id: 'organizacion', label: t('organizacion') },
    { id: 'logotipo', label: t('logotipo') },
    { id: 'invitaciones', label: t('invitaciones') },
  ]}
  current={paso}
  onStepSelect={(index) => setPaso(index)}
  label={t('progreso')}
  compactLabel={(paso, total) => t('pasoDeTotal', { paso, total })}
  labels={{ completed: t('completado'), current: t('actual'), pending: t('pendiente') }}
/>
```
