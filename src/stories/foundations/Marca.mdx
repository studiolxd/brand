# Marca

Los activos de marca de Studio LXD como ficheros sueltos: el logotipo, el isotipo y el juego de iconos de aplicación que consumen las apps de la suite. Esta página es el catálogo — la API de componente de cada pieza vive en su propia doc ([`Logo`](?path=/docs/atoms-logo--docs), [`Logomark`](?path=/docs/atoms-logomark--docs)).

## Logo

El logotipo completo: firma y letras. Es el que firma una interfaz — cabecera, formulario de acceso, pie de página.

<Canvas of={LogoStories.PorDefecto} />

- Componente React: [`Logo`](?path=/docs/atoms-logo--docs) (`@studiolxd/brand/logo`).
- Como datos: `logoSvg`, `logoPaths`, `logoViewBox` (mismo subpath).
- Fichero suelto: [`logo.svg`](/brand/logo.svg) — también publicado en el paquete como `@studiolxd/brand/assets/logo.svg`.

## Logomark

El isotipo: la parte gráfica del logotipo, sin la firma. Cuadrado, para donde el logotipo completo no cabe — un favicon, el icono de una aplicación, el avatar de una organización.

<Canvas of={LogomarkStories.PorDefecto} />

- Componente React: [`Logomark`](?path=/docs/atoms-logomark--docs) (`@studiolxd/brand/logomark`).
- Como datos: `logomarkSvg`, `logomarkSafeSvg`, `logomarkPaths`, `logomarkViewBox` (mismo subpath).
- Ficheros sueltos: [`logomark.svg`](/brand/logomark.svg) y [`logomark-safe.svg`](/brand/logomark-safe.svg) — también publicados como `@studiolxd/brand/assets/logomark.svg` y `@studiolxd/brand/assets/logomark-safe.svg`.

### El área de seguridad del 10 %

`logomark-safe.svg` es el mismo trazado que `logomark.svg` con un margen del **10 % por lado**: el isotipo ocupa el 80 % central del `viewBox` y entra completo en una máscara circular. Sirve para cualquier composición que recorte en redondo o en un marco ajeno al propio SVG — un `apple-touch-icon`, un avatar, el favicon — sin tener que calcular el margen cada vez. Es la fuente del juego de iconos de esta página.

## Un solo favicon para toda la suite

Decisión de marca (2026-09-11): **un solo favicon para todas las aplicaciones de la suite, sin variantes por producto.** Ninguna app pinta su propio icono — todas sirven el mismo juego, generado una vez aquí y consumido tal cual.

El dibujo es `logomark-safe.svg` sobre **dos tokens**, con el mismo criterio que ya usa el aviso del DS (CLAUDE.md § «Tokens de feedback», regla 8: relleno claro + tinta prusia, nunca tinta suelta): un **relleno** violeta y una **tinta** prusia encima, nunca el isotipo suelto sobre el fondo del sistema operativo.

- **Relleno** — `color.lavender` (`#BAABFF`, el mismo que usa `color.accent-1`). La paleta (`tokens/color/palette.json`) no tiene un primitivo llamado "violeta": este es el más próximo por familia.
- **Tinta** — `color.primary` (`#111E30`, el prusia). El mismo rol que pinta el texto sobre un `*-fill` de feedback: nunca blanco suelto, nunca un gris inventado.

Ninguno de los dos es un hex nuevo — la regla del sistema es no inventar color (CLAUDE.md § «No se inventan colores»): si hiciera falta un violeta más saturado, sería una decisión de paleta explícita y aparte, no un efecto lateral de este encargo.

## Los ficheros generados

`scripts/build-icons.mjs` (`pnpm build:icons`, dentro de `pnpm build:all`) genera este juego en `dist/assets/icons/` — determinista: misma entrada, mismos bytes, cada vez.

| Fichero | Talla | Uso | Descarga |
| --- | --- | --- | --- |
| `icon.svg` | vectorial | `<link rel="icon" type="image/svg+xml">` | [icon.svg](/brand/icons/icon.svg) |
| `favicon.ico` | 16 / 32 / 48 | `<link rel="icon">` (navegadores sin soporte SVG) | [favicon.ico](/brand/icons/favicon.ico) |
| `icon-192.png` | 192×192 | manifest — icono PWA | [icon-192.png](/brand/icons/icon-192.png) |
| `icon-512.png` | 512×512 | manifest — icono PWA | [icon-512.png](/brand/icons/icon-512.png) |
| `icon-512-maskable.png` | 512×512 | manifest — icono `purpose: "maskable"` | [icon-512-maskable.png](/brand/icons/icon-512-maskable.png) |
| `apple-touch-icon.png` | 180×180, sin transparencia | `<link rel="apple-touch-icon">` | [apple-touch-icon.png](/brand/icons/apple-touch-icon.png) |
| `manifest.webmanifest` | — | `<link rel="manifest">` | [manifest.webmanifest](/brand/icons/manifest.webmanifest) |

`icon-512-maskable.png` lleva un margen del **20 % por lado** (no el 10 % de `logomark-safe.svg`): el spec ["maskable" del Web App Manifest](https://www.w3.org/TR/appmanifest/#icon-masks) exige que el contenido visible quepa en el 80 % central del icono, porque cada plataforma lo recorta a su propia forma (círculo, squircle, redondeado…) y solo esa zona segura sobrevive en todas.

Todos —el `icon.svg` incluido— llevan el relleno y la tinta pintados en el propio fichero: ninguno depende de que el sistema operativo lo rellene, así que se ven igual en cualquier lanzador, pestaña o pantalla de inicio.

El favicon del propio Storybook (`public/favicon.svg`) es el mismo `icon.svg` generado — el script lo copia ahí en cada build, no hay un segundo dibujo que mantener sincronizado.

## Cómo lo consume una app

```ts
import {
  BRAND_ICON_ASSETS,
  BRAND_ICON_BG_COLOR,
  BRAND_ICON_INK_COLOR,
  BRAND_SOURCE_ASSETS,
} from '@studiolxd/brand/brand-assets';
```

`BRAND_ICON_ASSETS` da la ruta (`assets/icons/...`, bajo `@studiolxd/brand/assets/...`), la talla y el propósito de cada fichero generado; `BRAND_SOURCE_ASSETS` lo mismo para el logotipo y el isotipo sueltos. Un script de instalación puede recorrer la lista y copiar cada fichero a `public/` sin tener que conocer los nombres de memoria. `BRAND_ICON_BG_COLOR` (`#BAABFF`) y `BRAND_ICON_INK_COLOR` (`#111E30`) son el relleno y la tinta en texto, para quien necesite pintar el `theme-color` de una `<meta>` a mano.

Cada app sigue poniendo su propio `name`/`short_name` en su manifest — el `manifest.webmanifest` publicado aquí es la plantilla mínima (`"SLXD"`, los tres iconos, `theme_color`/`background_color`), no el manifest final de nadie.

## Tokens

El relleno (`BRAND_ICON_BG_COLOR`) y la tinta (`BRAND_ICON_INK_COLOR`) no tienen tokens de componente propios — salen directo de los primitivos `color.lavender` y `color.primary` en el script de build, porque el correo, el favicon y los iconos de aplicación son los tres rincones del sistema que no consumen CSS y necesitan el valor como dato (ver [Tokens desde JavaScript](?path=/docs/foundations-tokens-desde-javascript--docs)). Los tokens de `Logo` y `Logomark` —tallas, color del trazado, par oscuro— están en sus propias fichas.
