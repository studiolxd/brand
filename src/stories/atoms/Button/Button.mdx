# Botón

El botón es el elemento de acción principal del sistema. Existen cuatro variantes con roles distintos.

## Primary

Borde en color primario, fondo blanco y texto por defecto. En hover el fondo pasa a primario y el texto a inverso. Usado para acciones principales sobre fondos claros.

<Canvas of={ButtonStories.Primary} />

## Accent

Fondo en color accent-1 y texto oscuro. En hover el fondo pasa a accent-2. El texto es siempre oscuro para garantizar contraste suficiente.

> **Nota:** La prop `destructive` no tiene efecto sobre la variante `accent`. El color de fondo del accent es parte de su identidad visual y no es compatible semánticamente con la intención destructiva. Usa `variant="primary" destructive` o `variant="ghost" destructive` para acciones de alto riesgo.

<Canvas of={ButtonStories.Primary} />

## Outline

Borde y texto en color inverso sobre fondo transparente. En hover el fondo y el borde pasan a blanco y el texto a color por defecto. Para usar sobre fotografías o fondos oscuros.

<Canvas of={ButtonStories.OutlineOnDark} />

<Canvas of={ButtonStories.OutlineOnLight} />

## Ghost

Sin borde ni fondo. El texto toma el color por defecto de la superficie (oscuro sobre fondo claro, claro sobre fondo oscuro). En hover aparece subrayado. Para acciones secundarias de bajo peso visual, como cancelar, volver o acciones en línea dentro de un bloque de texto.

<Canvas of={ButtonStories.GhostOnLight} />

<Canvas of={ButtonStories.GhostOnDark} />

## Text

Un `<button>` con la cara de un enlace: sin caja ni altura fija, subrayado en reposo y sin subrayar en hover. Toma sus tokens del átomo `Link` (`button.text.*` → `link.*`), así que enlace y botón-enlace no divergen. Es para acciones que no navegan pero se leen como enlace (deshacer, abrir un panel). Con `destructiveIntent` usa el rojo de texto de error.

<Canvas of={ButtonStories.TextOnLight} />

## Block

Cualquier variante admite el modificador `block` para ocupar todo el ancho del contenedor.

<Canvas of={ButtonStories.Block} />

## Tamaños

Tres tamaños disponibles: `sm`, `md` (por defecto) y `lg`. El tamaño se aplica mediante la prop `size` y es la **talla de componente** del sistema (32/40/48px, ver Foundations → Tallas): el botón fija su altura a la talla y centra el contenido; solo cambian el padding horizontal y el cuerpo de letra. La variante `text` es inline y no tiene caja.

<Canvas of={ButtonStories.Sizes} />

## Solo icono

La prop `iconOnly` renderiza un botón cuadrado (su lado es la altura de la talla) pensado para acciones de solo icono: cerrar un modal, abrir una barra lateral, acciones de tabla. Es componible con cualquier `variant` y con los tres tamaños (`sm`, `md`, `lg`).

<Canvas of={ButtonStories.IconOnly} />

<Canvas of={ButtonStories.IconOnlyGhost} />

> **Accesibilidad:** un botón de solo icono no tiene texto visible que lo nombre, así que **siempre** necesita un `aria-label` (o un texto con el átomo `VisuallyHidden`). Sin él, el botón es inaccesible para lectores de pantalla.

```tsx
<Button iconOnly variant="ghost" size="sm" aria-label="Cerrar">
  <Icon name="close" />
</Button>
```

## Como enlace

### href

Cuando se pasa la prop `href`, el botón renderiza un `<a>` nativo. Apropiado para enlaces externos o cuando no se usa un router.

<Canvas of={ButtonStories.AsLink} />

El estado `disabled` en este caso añade `aria-disabled="true"` y `role="link"`, elimina el `href` y **corta el `onClick`**, ya que el atributo `disabled` nativo no existe en `<a>`: sin esas tres cosas el navegador seguiría el enlace y el manejador se dispararía igual. Lo mismo vale para el elemento que llegue por `render`, donde `disabled` tampoco significa nada por sí solo.

<Canvas of={ButtonStories.AsLinkDisabled} />

### render (Next.js Link y otros routers)

Con la prop `render`, Button aplica sus clases y event handlers sobre el elemento que se le pasa, sin añadir ningún wrapper (patrón `render` de Base UI). Esto preserva la navegación client-side del router:

```tsx
import Link from 'next/link';
import { Button } from '@studiolxd/brand';

<Button render={<Link href="/proyectos" />} variant="primary">
  Ver proyectos
</Button>
```

**Solo desde componentes cliente.** `Button` es un componente cliente y `render` es un elemento de React: si se pasa desde un Server Component, el elemento no sobrevive al cruce servidor→cliente y el botón falla en tiempo de ejecución («Element type is invalid»). En un Server Component usa `href` (renderiza un `<a>`); `render={<Link />}` va en componentes marcados con `'use client'`.

En Storybook se muestra con un `<a>` como stand-in del componente `Link` del router:

<Canvas of={ButtonStories.ConRender} />

## Composición y atributos HTML

`Button` extiende los atributos nativos de `<button>` y reenvía cualquier prop no declarada (`data-*`, `aria-*`, `id`, atributos de formulario como `form`, `name`, `value`…) al elemento renderizado, en las tres ramas (`<button>`, `<a>` y `render`). Esto permite:

- **Componer con Base UI** (`<Dialog.Close render={<Button/>} />`): las props que el primitivo inyecta (`onClick`, `aria-*`, `data-*`…) llegan al Button y se aplican al elemento.
- **Añadir clases** con `className`: se concatena **después** de las clases propias del componente, de modo que el consumidor añade estilos sin sustituir los del design system.

```tsx
<Button data-slot="button" data-variant="secondary" className="mi-clase">
  Guardar
</Button>
// → <button class="button button--primary mi-clase" data-slot="button" data-variant="secondary">
```

> **Nota:** el default de `type` sigue siendo `"button"`. Dentro de un `<form>`, si quieres enviarlo pasa `type="submit"` explícitamente (el default nativo de HTML sería `submit`, pero aquí no lo es).
