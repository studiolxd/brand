# MultiSelect

Elegir **varias** opciones de una lista cerrada. Lo elegido se queda a la vista en píldoras
dentro de la caja, cada una con su aspa para quitarla.

Es el **control suelto**. Con etiqueta, ayuda y mensaje de error, el componente es
`MultiSelectField`. Para una lista que se pide al servidor según se escribe, `AsyncMultiSelect`.

## Teclado

Patrón **combobox** de WAI-ARIA, el mismo que `AsyncSelect`. El foco del DOM no sale nunca de
la caja: la opción activa se señala con `aria-activedescendant`.

| Tecla | Qué hace |
| --- | --- |
| `↓` / `↑` | Abre la lista y recorre las opciones |
| `Inicio` / `Fin` | Salta a la primera y a la última |
| `Intro` / `Espacio` | Marca y desmarca la opción activa |
| `Esc` | Cierra sin cambiar nada |
| Una letra | Salta a la opción que empieza por ella |

Las aspas de las píldoras viven **fuera** del `role="combobox"` y con `tabIndex={-1}`: un
combobox no admite controles dentro, y un botón anidado ahí no lo anunciaría ningún lector.
Para quitar valores con el teclado se desmarcan desde la lista.

## Superficie oscura anidada

El desplegable se monta en un portal, en `document.body`, que hereda el tema activado en la
raíz (`html.dark`, `[data-theme="dark"]`) sin más. Solo cuando el control vive dentro de un
`.surface-dark` **anidado** hay que pasar `container` con el nodo donde montarlo.

## Uso

```tsx
import { MultiSelect } from '@studiolxd/brand/multi-select';

<MultiSelect
  options={[{ value: 'dev', label: 'Desarrollo' }, { value: 'ux', label: 'Diseño' }]}
  aria-label="Áreas"
  onValueChange={setAreas}
/>
```

Con `name` se monta un input oculto por valor elegido, así que el control funciona en un
formulario sin JavaScript de por medio. El `ref` va al elemento con `role="combobox"`, que es
lo enfocable: react-hook-form puede llevar el foco ahí al fallar la validación.
