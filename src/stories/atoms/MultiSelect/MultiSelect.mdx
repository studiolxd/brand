# MultiSelect

Elegir **varias** opciones de una lista cerrada. Lo elegido se queda a la vista en píldoras
dentro de la caja, cada una con su aspa para quitarla.

Es el **control suelto**. Con etiqueta, ayuda y mensaje de error, el componente es
`MultiSelectField`. Para una lista que se pide al servidor según se escribe, `AsyncMultiSelect`.

## Superficie oscura

La caja y el desplegable invierten fondo, tinta y borde. Las píldoras no pueden quedarse en
prusia —sería el color del propio lienzo—: pasan al par de `Button primary`, lavanda con

## Internacionalización

Los dos textos que el control emite por su cuenta —el marcador de sitio y el nombre accesible del
aspa de cada ficha— **no tienen valor por defecto**: salen del `BrandMessagesProvider`.

```tsx
<BrandMessagesProvider
  messages={{
    multiSelect: {
      placeholder: t("select.placeholder"),
      remove: (label) => t("multiSelect.remove", { label }),
    },
  }}
>
  {children}
</BrandMessagesProvider>
```

<Canvas of={MultiSelectStories.TextosDelProveedor} />

| Prop | Clave del catálogo | Dónde aparece |
| --- | --- | --- |
| `placeholder` | `multiSelect.placeholder` | texto de la caja sin valores elegidos |
| `removeLabel` | `multiSelect.remove` | `aria-label` del aspa de cada ficha |

`remove` recibe la etiqueta de la opción y devuelve la frase entera: el orden de las palabras
cambia de un idioma a otro, así que se traduce la frase, no se concatena. La etiqueta en sí es un
dato de `options` y no sale del catálogo. El orden es **prop → proveedor → error**.

La convención completa está en **Foundations › Internacionalización**.

## Teclado

El motor es el `Select` múltiple de **Base UI** (no su `Combobox`: sin campo de texto, la guía de
Base UI manda al `Select`), y el teclado es suyo. La caja lleva `role="combobox"`; al abrir, **el
foco pasa a la lista** —la opción activa es la enfocada, y Base UI la marca con
`data-highlighted`— y al cerrar vuelve a la caja. La lista es `aria-multiselectable` y cada
opción marcada lleva `aria-selected`.

| Tecla | Qué hace |
| --- | --- |
| `↓` / `↑` / `Intro` / `Espacio` | Con la lista cerrada, la abren |
| `↓` / `↑` | Recorren las opciones |
| `Inicio` / `Fin` | Saltan a la primera y a la última |
| `Intro` / `Espacio` | Marcan y desmarcan la opción activa; la lista sigue abierta |
| `Esc` | Cierra sin cambiar nada y devuelve el foco a la caja |
| Una letra | Salta a la opción que empieza por ella |

Que el foco entre en la lista no cuenta como salir del control: `onBlur` (con el que valida
react-hook-form) solo se avisa cuando el foco deja a la vez la caja y la lista.

Las aspas de las píldoras viven **fuera** del `role="combobox"` y con `tabIndex={-1}`: un
combobox no admite controles dentro, y un botón anidado ahí no lo anunciaría ningún lector.
Para quitar valores con el teclado se desmarcan desde la lista.

## Superficie oscura anidada

El desplegable se monta en un portal, en `document.body`, que hereda el tema activado en la
raíz (`html.dark`, `[data-theme="dark"]`) sin más. Solo cuando el control vive dentro de un
`.surface-dark` **anidado** hay que pasar `container` con el nodo donde montarlo.

## Uso

```tsx
import { MultiSelect } from '@studiolxd/brand/multi-select';

<MultiSelect
  options={[{ value: 'dev', label: 'Desarrollo' }, { value: 'ux', label: 'Diseño' }]}
  aria-label="Áreas"
  onValueChange={setAreas}
/>
```

Con `name` se monta un input oculto por valor elegido, así que el control funciona en un
formulario sin JavaScript de por medio. El `ref` va al elemento con `role="combobox"`, que es
lo enfocable: react-hook-form puede llevar el foco ahí al fallar la validación.
