# ErrorPage

La plantilla de «algo ha salido mal». El marco lo pone `PublicPageShell` —cabecera y pie opcionales, y el `main` acotado—; lo propio de esta plantilla es el contenido: **dos columnas** (`Columns`), mismo molde que `AuthPage`. Izquierda: `PageIntro` (título y frase) y el enlace de vuelta «Volver al inicio». Derecha: la frase de reintento y el `Button` «Reintentar» en bloque — todo lo pone el producto.

## Qué chrome se pasa en cada límite

Una página de error no puede depender del layout que pudo fallar. La regla, para una app Next:

- **`error.tsx`** (límite de un layout con proveedores): se pasa la **cabecera sin auth** y el pie. Hay i18n y tema; lo que no hay es sesión garantizada, así que ningún menú de usuario.
- **`global-error.tsx`** (límite del layout raíz): **no se pasa ni cabecera ni pie**. Sin proveedores no hay i18n ni tema, y cualquier pieza que los use lanzaría.

```tsx
// error.tsx
'use client';
export default function Error({ reset }) {
  return (
    <ErrorPage
      title={t('title')}
      description={t('description')}
      homeAction={<Link icon="arrow-left" render={<NextLink href="/" />}>{t('home')}</Link>}
      retryDescription={t('retryDescription')}
      retryAction={<Button type="button" block onClick={reset}>{t('retry')}</Button>}
      header={<PublicHeader auth={false} />}
      footer={<PublicFooter />}
    />
  );
}
```

## Cabecera y pie, a salvo

Aun así, `header` y `footer` van cada uno dentro de un `ErrorBoundary` (fallback `null`), puesto por `PublicPageShell`: si la cabecera lanza al renderizar, desaparece ella y la página sigue con su mensaje y sus salidas.

## Dentro de una app

Una app con `AppShell` ya tiene su `main`; una página de error dentro no puede montar otro marco ni otro `main`. Con `shell={false}` la plantilla devuelve **solo el contenido** —las dos columnas (`Columns`)— y lo pinta la app donde le toca. Sin marco, `header`, `footer` e `id` no aplican.
